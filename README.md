# AVITO LEGAL OS — GitHub CRM

Статическая CRM для работы с клиентами Avito. Приложение работает без сборки: достаточно загрузить содержимое этой папки в репозиторий и открыть `index.html` через GitHub Pages.

## Что внутри

- `index.html` — точка входа приложения;
- `manifest.webmanifest` — метаданные для открытия CRM как отдельного приложения;
- `styles.css` — гибрид Glassmorphism + Claymorphism + Bento Grid, стеклянные панели, объёмные controls и анимации;
- `app.js` — логика, поиск, фильтры, карточка клиента, копирование сообщения для Gemini, импорт и экспорт, опциональные звуки интерфейса;
- `data/crm.json` — рабочая база: 215 карточек (97 исходных CRM-клиентов + 118 новых архивных обращений) без текстов переписок, с производными статусами, финансовыми метаданными и редактируемыми полями;
- `data/crm-strict.json` — компактная совместимая версия только с разделами `clients` и `finance`;
- `assets/dashboard-orb.png` — декоративный generated-ассет для фонового motion-слоя.

## Загрузка в GitHub Pages

1. Создайте **приватный** репозиторий на GitHub.
2. Распакуйте архив и загрузите в репозиторий файлы `index.html`, `styles.css`, `app.js`, `manifest.webmanifest` и папки `data` и `assets`.
3. Откройте **Settings → Pages**.
4. В разделе **Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/ (root)`.
5. Откройте выданный GitHub Pages URL.

Сборщик, Node.js и база данных на сервере не нужны. Приложение загружает `data/crm.json` при открытии, а импортированный через интерфейс JSON пытается сохранить в браузере текущего устройства; большая база может превысить лимит localStorage; ручные изменения карточек при этом сохраняются отдельно как компактные overrides. Кнопка **Экспорт JSON** позволяет скачать текущую копию.

## Дизайн

Интерфейс объединяет три слоя: Glassmorphism для прозрачных панелей и глубины, Claymorphism для мягких объёмных кнопок, полей и аватаров, Bento Grid для модульной раскладки KPI и аналитики. На мобильном экране сетка автоматически переходит в одну колонку.

## Рабочий сценарий

- **Обзор** — быстрые показатели, статусы и последние изменённые карточки на animated glass-панели.
- В боковой панели есть отдельный переключатель звуков интерфейса; звуки выключены по умолчанию и генерируются локально через Web Audio API.
- **Клиенты** — поиск по имени, нику, услуге, темам и полям карточки; фильтры по стадии, оплате, категории и сортировка.
- **Карточки** — редактирование имени, ника, статуса, цены, оплаты, города, описания и follow-up.
- **Финансы** — исходные записи CRM и платёжные метаданные без текста переписки.
- **Аналитика** — категории, темы и состояние карточек без хранения переписки.
- **Данные и импорт** — загрузка нового JSON, экспорт текущей базы и сброс локального импорта.

Тексты переписок в этой версии не хранятся и не загружаются в CRM.

## Правила рабочего списка

- 97 карточек из исходного backup сохранены с их ручными полями и статусами.
- Новые архивные обращения не попадают в «Ожидание» или «В работе»: для них используется только «Завершён» либо «Отказ».
- В интерфейсе снова доступны кнопки **«Добавить клиента»** и **«Изменить»**; статус, цену, оплату, город, описание и срок можно менять вручную.
- Тексты переписок и архив диалогов удалены из этой версии CRM; сохранены только карточки и редактируемые поля.

## Конфиденциальность

Файл `data/crm.json` содержит персональные данные клиентов и рабочие CRM-поля. Репозиторий должен быть приватным. Не публикуйте эту папку в открытом репозитории и не отправляйте архив третьим лицам без правового основания. Если нужен публичный демонстрационный репозиторий, перед загрузкой удалите `data/crm.json` и оставьте только `data/crm-strict.json` после обезличивания.

## Обновление базы

1. Подготовьте JSON с разделом `clients` (можно использовать экспорт CRM).
2. В приложении откройте **Данные и импорт → Импорт JSON**.
3. После проверки данных нажмите **Экспорт текущей базы**, если нужно сохранить изменения.
4. Для постоянного обновления GitHub замените файл `data/crm.json` новым экспортом.

Приложение не объединяет одинаковые имена в одного человека: устойчивым идентификатором остаётся исходный ID диалога (`D001`, `D002` и т. п.). Платёжные упоминания из текста отмечены как сигналы и не выдаются за банковскую проверку.
